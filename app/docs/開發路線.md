## 一、現況一句話

原本是「桂圓帳房」—— 一套把 Excel 流水帳變成本機管理平台的東西(訂單 / 客戶 / 庫存 / 批次 / 通路 /
六個報表 / 財務健康 / 產季目標)。**現在正在做 v2 改造**,把它從「銷售視角」升級成「經營者 + 報稅」視角。

---

## 二、v2 要解決的問題

郡碩農創有限公司目前用 Excel 只記龍眼乾與蜂蜜的年度銷售額,**人工成本、田間管理成本、驗證費用、
研發攤提全沒計入**,不知道每條產品線到底賺不賺錢,沒有底氣擴大經營。同時他們是**一般稅額計算、
雙月申報、兼營免稅**的公司,需要報 403 和營所稅(現況見 [報稅參考.md](報稅參考.md))。

**兩個目標**:
- **A. 產品線全成本損益** —— 各條收入線各自賺不賺(給老闆做「敢不敢擴大」的決策)
- **B. 報稅支援** —— 產出乾淨的帳載數字 + 附表(403、營所稅),交給誰報不管(現在是老闆田家易自己報,
  將來變大再找記帳士,匯出格式從一開始就做成 handoff-ready)

## 二之一、商業模式(重要 —— 比一開始想的大很多)

**郡碩農創不只是賣龍眼乾和蜂蜜的農場。** 2026-09 郡碩補充的成本結構 / 收益來源顯示,這是一家
**地方創生 / 農業科技公司**:用自家龍眼果園當「示範場域」開發帶感測器的智慧焙製設備與工法,
一邊賣設備 / 授權 / 服務給別的農戶,一邊賣做出來的premium農產品。

**收益來源(4 類)**:
1. **設備導入收入**:銷售設備、租賃服務、安裝與客製化整合費用
2. **服務型收入**:技術開發費、配方 / 工法授權、維保月費、教育訓練收入
3. **產品銷售**:禮盒與零售產品利潤、B2B 批發、企業團購合約 ← **目前桂圓帳房只處理這一塊**
4. **共同專案收入**:品牌聯名分潤、活動收益、企業 CSR 贊助

**成本結構(4 類)**:
1. **固定成本**:研發人力、示範場域建置、平台維運
2. **變動成本**:感測器與設備採購成本、包材與生產成本、物流與人力支出
3. **市場推廣成本**:品牌設計費、媒體投放、活動執行
4. **合作成本**:技術授權、第三方驗證 / 認證費用、教育訓練費

**這對設計的意涵**:
- 「哪條線賺不賺」的「線」= **這 4 類收入**(設備 / 服務 / 產品 / 共同專案),龍眼 vs 蜂蜜是「產品」底下的子問題。
- 現在的 `business_unit`(龍眼 / 蜂蜜)**太窄**。回合 2 開工前要重想:事業別頂層可能是
  農產品 / 設備 / 服務 / 共同專案,龍眼 / 蜂蜜降一層。
- 收入型態變多:租賃、維保**月費**(遞延 / 循環)、授權金(一次或抽成)、技術開發**專案**(里程碑請款)、
  CSR 贊助(補助性質)—— 現在的 `order`(訂單 + 明細 + 出貨)裝不下,回合 2/3 要處理。
- 申報表的「研發費 78 萬、薪資 58 萬」對得上了 —— 這是研發型公司,產品銷售只是其中一塊。
- **這一段還沒跟使用者細談** → 回合 2 的範圍要先重新討論再動工。

## 三、核心框架:一套資料、兩種報表

同一套底層交易/成本資料,上層分兩種報表:

| 層 | 用途 | 特性 |
|---|---|---|
| **地基** | 每筆交易/成本帶足維度 | 產品線、日期→(產季 / 曆年月 / 403期)、稅別、直接/共同、每個成本項可裝「帳載值 + 管理調整值」、固定資產卡、進項憑證 |
| **A 產品線損益** | 管理決策 | 共同費用分攤基準可切換、研發按年限攤、老闆的工按市價計、不管稅務時點 |
| **B 報稅** | 給稅局 / 記帳士 | 曆年 / 403期、只認實際金額、帳載欄對應申報書行號、兼營比例年度調整 |

A 和 B 的地基約 8 成共用,所以「兩種報表」不是兩倍工。

## 四、設計哲學(重要)

**不是把田家易的手動流程自動化**（那等於假設手動是對的,但他舊帳多半是錯的、他本人也不懂）。
**是建一套「對的制度」讓他能做對的事。**

- 制度結構照會計/稅法規則(商業會計處理準則、營所稅查核準則、固定資產耐用年數表、
  兼營營業人營業稅額計算辦法、分批成本法),不照任何人的習慣。
- **該給選項的給選項**（稅別 應稅/免稅、分攤基準、折舊年限、研發攤提年數 → 做成設定,給合理預設,可改)。
- **有標準答案的不給選項、擋掉錯的**（COGS = 期初+進貨−期末、設備要折舊不能整筆費用化、損益表結構)。
- 判斷題(免稅認定)做成選項、預設「待確認」,記錄「決定 + 依據」,不寫死猜測。
- 表單要教、要擋、要有預設（田家易不懂概念）。
- 不匯入舊爛帳 —— 用「**切轉日**」建期初餘額,之後每筆正確記錄(見第八節)。

## 五、已確認的事實

**產品線 —— 目前只做了「產品銷售」這一塊的三層結構(回合 1 實作)**:

```
事業別          產品群組        SKU
龍眼(自有果園)  龍眼鮮果        龍眼鮮果 台斤
               龍眼乾          桂圓乾各規格 / 禮盒 / 桂圓棒
               龍眼肉          龍眼肉 600g / 1000g
蜂蜜(自養蜂)    蜂蜜            龍眼蜂蜜 / 荔枝蜂蜜
```

> ⚠️ 見「二之一、商業模式」——「線」其實有 4 類收入(設備 / 服務 / 產品 / 共同專案),
> 上面只是「產品」底下的細分。回合 2 開工前頂層結構要重想。

- 龍眼三產品**共用同一果園、同一批鮮果** → 田間管理成本按耗用鮮果量分攤到三者;
  龍眼乾、龍眼肉再加焙製(柴/電、顧爐工、監控焙灶折舊);龍眼肉再加剝肉工。
- 蜂蜜自養採收 → 蜂群飼養、蜂箱折舊、採蜜/搖蜜/濾蜜工,跟龍眼完全分開。
- **設備 3 台**:2 台傳統機具、1 台有監控系統(待問:取得成本 / 日期 / 是否政府補助 / 是否即申報表研發費 78 萬的一部分)。
- **果園自有**(申報表租金 0)→「田間管理」才是真正的土地相關成本。
- 產季定義 = **當年 4 月初 ~ 隔年 3 月底**,以起始年命名(`queries.season_of()`)。

**禮盒風格**:郡碩的「圓來好禮」禮盒 —— 磚紅/赭底、奶油米、龍眼點點圖、圓角盾形標籤。
style 微調併進 v2 一起做,不另開回合(主色往磚紅移、卡片底色奶油米)。

## 八、名詞

**切轉日(cutover date)**:畫一條線,線之前的舊帳不管(留在國稅局那邊),線這天把「現在手上有什麼」
盤點記對一次(= 期初餘額:庫存 / 固定資產 / 留抵稅額 / 現金銀行 / 應收應付),之後每筆用系統正確記錄。
**建議切轉日 = 2026-09-01**(2026 龍眼產季剛開始,整季乾淨進系統)。代價:2026 曆年營所稅半舊半新,
第一個完全乾淨的營所稅年度是 2027。

**產季**:當年 4 月初 ~ 隔年 3 月底(4 月開花養果 → 隔年 3 月這批賣完),以起始年命名。
銷售集中在 9 月 ~ 隔年 2 月。不是曆年。

**帳載值 vs 管理調整值**:同一筆成本,B 層(稅)用實際/申報數,A 層(管理)可調整
(研發按年限攤、老闆的工按市價、折舊按經濟壽命)。資料模型每個成本項要能同時裝這兩種。
