給想完整了解系統怎麼記帳的人看(同事)。日常操作流程的白話版說明見
[使用手冊.md](使用手冊.md);資料庫欄位 / 路由等程式細節見 [系統文件.md](系統文件.md)。

## 一、系統怎麼運作:兩層資料

系統把資料分成兩層,**家易只填業務表單,總帳是系統依對照表自動組出來的**,不用另外
手動記帳:

```
業務表單(訂單 / 進貨 / 費用 / 生產入庫 / …)
        │  存檔時,依 app/ledger.py 的對照表自動組成複式分錄
        ▼
總帳(ledger_entry)── 借方合計一定等於貸方合計
```

對照表(哪個類別記哪個會計科目)全部集中在 `app/ledger.py`,想調整科目代碼直接改那個
檔案的常數就好,不用動其他程式。這份對照表是**第一版、依常理判斷的猜測**,已經對照過
「會計科目表」正式版逐一核對修正,但還有幾個正式表沒有列出對應科目的項目,標成「待確認」
(見第六節)。

### 選單結構

側邊選單分四個可收合的群組(每天做的 / 出貨・退貨 / 看數字 / 設定一次的),
最上面固定有「儀表板」跟「＋ 記一筆(九宮格)」兩個入口。

![儀表板(可看到完整選單)](screenshots/manual/dashboard.png)

### 記一筆九宮格總覽

「記一筆」頁把 9 種交易類型攤開成卡片,對應同事原本設計的「帳務設定表」9 宮格分類。
其中 4 種(銷售/出貨、採購物料、營運支出、設備相關)本來就有家易熟悉的業務畫面,直接
沿用;其他 4 種(生產入庫、其他收益、資本異動、帳務調整)是新蓋的記帳原生畫面;
「其他費用」則是併進「營運支出」既有畫面的類別選單,沒有另開新畫面。

![記一筆九宮格](screenshots/manual/entry.png)

## 二、9 宮格逐一說明

### 1. 銷售 / 出貨(訂單)

家易熟悉的訂單畫面,**不經過確認畫面,存檔背景自動記**——訂單是最高頻操作,不想多插
一個步驟。一張訂單對到**兩張獨立傳票**:

| 傳票 | 記帳時機 | 分錄 |
|---|---|---|
| `order_sale`(前綴 `S`) | 訂單存檔當下,不管收沒收到錢 | 借:應收帳款(全額)/ 貸:銷貨收入(依產品線拆多筆,`4111-01`~`04`,沒歸屬產品線用通用 `4110`)+ 借:銷貨成本(`5111`,單一科目不拆線)/ 貸:存貨(依產品線拆,`COGS_INVENTORY_ACCOUNTS`) |
| `order_payment`(前綴 `R`) | 標記已收款那一刻,實收金額 > 0 才記 | 借:現金 / 銀行存款(依訂單的付款帳戶)/ 貸:應收帳款 |

訂單種類不是「銷售」(贈送、樣品、內部領用等)不記 `order_sale`(回傳空分錄)。
金額或品項改變、複製訂單、標記部分收款,對應傳票都會**整張重開**(先刪舊列再插新列,
不是疊加)。刪除訂單時,兩張傳票跟著清掉。

![訂單明細](screenshots/manual/order-detail.png)

### 2. 採購物料(進貨)

存檔前會先看一次「確認分錄」畫面,可以微調付款帳戶 / 稅額 / 憑證類型再真的存檔。
憑證類型選到「發票」,發票號碼是必填的。

| 類別 | 科目(借方) |
|---|---|
| 原料 / 包材 | `1315 原料`(正式表沒有專門的「包材」科目,兩者併記) |
| 委外加工 | `1314 在製品`(委外加工完成前算在製品成本) |
| 服務 / 其他 | `6188 其他費用` |
| 設備 | 不記這裡——勾「這是設備」走固定資產那條路(見第 4 項) |

貸方是現金 / 銀行存款(依付款帳戶),有稅額另外借記 `1423 進項稅額`。

![進貨確認分錄](screenshots/manual/purchase-confirm.png)

### 3. 營運支出

一樣先看確認畫面再存檔。類別 → 科目對照(第一版猜測,`ledger.EXPENSE_ACCOUNTS`):

| 類別 | 科目 |
|---|---|
| 直接人工 | `6110-01 薪資支出-直接人工` |
| 人事 | `6110-02 薪資支出-人事` |
| 場地・倉儲 | `6111 租金支出` |
| 行銷 | `6117 廣告費` |
| 設備維護 | `6116 修繕費` |
| 培訓 | `6131 訓練費` |
| 金流手續費 | `6188-04 其他費用-手續費` |
| 驗證費 | `6188-07 其他費用-檢驗費` |
| 田間管理 | `6188-11 其他費用-田間管理`(**待確認**,正式表沒有對應科目) |
| 研發 | `6188-12 其他費用-研發`(**留給真正沒有形成實體設備的費用用**——申報表那筆 78 萬研發費已確認是烘焙機器零件成本,該走固定資產,不是這裡;畫面選到這個類別會提醒使用者) |
| 其他 | `6188 其他費用` |
| 其他費用-什項購置 / 勞務費 / 設計費 / 手續費 / 交通費 / 包裝費 / 檢驗費 / 印刷費 / 規費 / 燃料費 | `6188-01`~`10`(直接對應正式科目表) |

「攤提月數」欄位**只影響財務健康頁的月損益顯示**(分月認列),總帳記的是存檔當下現金
真正流出的全額——這是刻意的:總帳反映真實現金流,財務健康頁是另一套管理用的估算,
兩者用途不同、數字本來就不會一樣。

![新增營運費用](screenshots/manual/expense-new-rnd-hint.png)

### 4. 設備相關(固定資產)

買入跟折舊分兩條路記帳:

**買入**——存檔整張重開,借設備科目(全額成本)/ 貸現金銀行存款(= 成本 − 政府補助款)/
貸 `4881-02 其他營業收入-政府補助收入`(補助款 > 0 才加這筆,重用「其他收益」的科目)。

| 類別 | 科目 |
|---|---|
| 機器設備 | `1616 機器設備` |
| 房屋建築 | `1611 房屋` |
| 電腦設備 / 生財器具 | `1691 辦公設備`(併記) |
| 運輸設備 | `1616-02`(**待確認**,正式表沒有運輸設備科目) |

**折舊**——沒有「存檔」這種天然觸發點(是時間流逝就該發生的事),改成**開 `/assets`
頁時,系統順便把還沒記過的月份補上**,已經記過的月份不動(不是整張重開,是缺的月份才
補)。借 `6124 折舊` / 貸 `1616-99 累計折舊`(共用科目,不分資產類別;正式表沒有專門
對應,比照正式表自己的 `1405`/`1406`生產性生物資產那組命名模式類推)。

> 第一次上線打開 `/assets` 頁,會把每台資產從取得月到當月**所有欠的月份一次補齊**,
> 總帳會一次出現好幾張折舊傳票,這是正確反映現實,不是重複記帳。

處分(填處分日)之後不再產生新的折舊月份,但**如果處分日設定得比系統已經補過的月份
早,已經記過的未來月份不會自動回沖**(這種情況正常使用下很少見,真遇到用「帳務調整」
手動沖銷)。資產處分當下的損益(帳面淨值轉列處分損益)目前沒有做,留到之後真的有處分
案例再看。

刪除資產卡,買入 + 所有折舊傳票一次清掉。

![固定資產](screenshots/manual/assets.png)
![新增固定資產](screenshots/manual/asset-new.png)

### 5. 生產入庫

掛在既有「庫存」頁的新卡片,不是獨立資源——沿用 `stock_move` 表,`move_type` 多一個
「生產入庫」。存檔時同時:①寫一筆庫存異動(比照「分裝入庫」)②借存貨(依商品的產品線)
/ 貸 `6498 其他利益`(對應同事表裡的「淨FV利益」,正式表沒有專門科目,先掛在既有的
「其他利益」)。

### 6. 其他收益

新畫面,借現金(含稅)/ 貸收入 + 貸 `2214 銷項稅額`(有稅才加)。

| 類別 | 科目 |
|---|---|
| 利息收入 | `4881-01 其他營業收入-利息收入` |
| 政府補助收入 | `4881-02 其他營業收入-政府補助收入` |
| 其他 | `4881-09 其他營業收入` |

![其他收益列表](screenshots/manual/other-income-list.png)
![新增其他收益](screenshots/manual/other-income-new.png)

### 7. 其他費用

**沒有獨立畫面**——正式科目表裡「其他費用」就是 `6188` 系列,跟營運支出同一個費用
區間,所以併進「營運支出」既有畫面的類別選單(見上面第 3 項的 `6188-01`~`10`)。
九宮格卡片點進去會導去營運支出畫面。

### 8. 資本異動

新畫面,兩種類型:

| 類型 | 分錄 |
|---|---|
| 現金增資 | 借現金(依付款帳戶)/ 貸 `3110 普通股股本` |
| 盈餘轉列公積 | 借 `3351 累積盈虧` / 貸 `3310 法定盈餘公積`(**待確認**——同事草稿有這個科目,正式表沒列,先沿用草稿代碼) |

![資本異動列表](screenshots/manual/equity-list.png)
![新增資本異動](screenshots/manual/equity-new.png)

### 9. 帳務調整

新畫面,其他 8 類都套不上時的例外出口——直接指定一組借方科目 + 貸方科目 + 金額,
系統記這一借一貸,不會另外加稅額或現金腳。借 / 貸科目下拉選單列出系統目前**所有**
已知的科目(`ledger.ALL_ACCOUNTS`,攤平所有對照表常數、去重、依代碼排序)。

這個畫面需要使用者自己判斷「這筆該記哪個科目、放借方還是貸方」,**定位上比較適合同事
用**,不是家易日常操作的一部分。

![帳務調整列表](screenshots/manual/adjustments-list.png)

## 三、銷貨退回 / 折讓(不在九宮格裡,但邏輯相關)

`sales_return` 記的退貨 / 折讓,比照訂單,不經過確認畫面、存檔背景自動記。沖銷方向
依原訂單**目前的付款狀態**決定(已跟使用者確認:已收款的訂單退貨 / 折讓,錢是真的退
現金給客戶,不是留抵):

| 原訂單狀態 | 分錄 |
|---|---|
| 已收款 | 借 `4170 銷貨退回` 或 `4190 銷貨折讓` / 貸現金銀行存款(真退錢) |
| 待收款 / 部分收款 | 借 `4170` 或 `4190` / 貸 `1172 應收帳款`(打折欠款) |

好貨退回可再賣(`restock=1`)時,再鏡射訂單成立那組分錄,借存貨(依產品線)/ 貸
`5111 銷貨成本`,把成本原路沖回;折讓或報廢退貨(`restock=0`)不沖成本(已經沉沒)。

兩個建立入口(訂單頁單筆表單、「整筆退單」一鍵)都會記帳;刪除退貨紀錄、刪除整張
訂單,對應傳票都會連動清掉。

**已知限制**:部分收款訂單如果退貨金額超過「還欠的部分」,理論上該拆一部分退現金、
一部分沖應收,目前先一律當沖應收處理,不拆分——這種混合情況很少見,真遇到用
「帳務調整」手動處理差額。

![退貨/折讓列表](screenshots/manual/returns.png)

## 四、總帳頁

![總帳明細](screenshots/manual/ledger.png)

### 篩選

- **來源下拉**:依交易類型篩(進貨 / 營運費用 / 訂單成立 / 訂單收款 / 生產入庫 / 其他收益 /
  資本異動 / 帳務調整 / 設備取得 / 折舊 / 退貨・折讓)。
- **日期範圍 + 關鍵字**(科目代碼 / 名稱 / 備註):純前端即時篩選,不用重新整頁查詢。

### 勾選刪除

勾選傳票、按「刪除勾選的傳票」——**刪除會連同來源那筆業務紀錄(那筆進貨 / 那張訂單…)
一起刪掉,而且會重用該來源自己原本的刪除邏輯**,不會繞過既有的檢查規則(例如訂單刪除
本來會一併清庫存異動、物流異常關聯,勾選刪除走的是同一套)。

**「設備取得」「折舊」這兩類沒有勾選框**——折舊一台設備會對到很多張月份傳票,勾一張
沒辦法只刪那個月、又不能整台資產跟著刪掉,這兩類要管理(改內容 / 處分 / 整台刪除)
一律回「固定資產」頁操作。

### 傳票號碼前綴

| 前綴 | 來源 |
|---|---|
| `P` | 進貨 |
| `E` | 營運費用 |
| `S` | 訂單成立 |
| `R` | 訂單收款 |
| `F` | 生產入庫 |
| `I` | 其他收益 |
| `Q` | 資本異動 |
| `M` | 帳務調整 |
| `K` | 設備取得 |
| `D` | 折舊 |
| `T` | 退貨 / 折讓 |

同一天同前綴,序號從 001 累加。

## 五、三張報表

這三張是家易 / 同事實際會打開來核對進度、判斷該不該催款、該不該補貨的報表——不是總帳
分錄本身。

### 應收帳款帳齡(獲利報表 → 收款帳齡分頁)

分桶(0–15 / 16–30 / 31 天以上)+ 未收款清單(可直接點「標記收款」)+ 最近已收回清單。
資料來源是 `order.payment_status`,不是查總帳的應收帳款科目餘額。

![收款帳齡](screenshots/manual/reports-aging.png)

### 銀行帳戶明細

依科目(`1102 現金` / `1103 銀行存款-X`)從總帳篩出來,逐筆算累計餘額。帳戶名單直接
從總帳裡實際用過的科目抓,不是另外維護的固定清單——這代表**同一個帳戶,每次填的
「付款帳戶」名稱一定要一致**,不然會被當成兩個帳戶、餘額對不起來。系統在有 datalist
自動完成的輸入框都會列出已經用過的名稱供選,降低打錯字的機率,但沒辦法完全防呆。

![銀行帳戶明細](screenshots/manual/cash.png)

### 存貨管理(含金額)

現有的庫存異動只有數量,這張報表乘上商品目錄的「單位成本」概算金額,依商品列出
期初 / 入庫 / 出庫 / 期末(數量 + 金額),跟現在算毛利用的是同一套單位成本邏輯
(不分批次)。

![存貨管理含金額](screenshots/manual/stock-value.png)

## 六、科目對照表全覽

以下是 `app/ledger.py` 目前所有的科目對照常數,**這是第一版、依常理判斷的猜測**,
已對照同事「會計科目表」正式版逐一核對過,標「待確認」的項目正式表完全沒有對應科目,
需要同事確認怎麼處理。要調整代碼,直接改 `app/ledger.py` 對應常數就好,不用改其他
程式。

| 科目代碼 | 科目名稱 | 用在哪裡 |
|---|---|---|
| `1102` | 現金(正式表叫「零用金」) | 各類現金收付的預設帳戶 |
| `1103` | 銀行存款-X | 付款帳戶不是「現金」時 |
| `1172` | 應收帳款 | 訂單成立(借)/ 收款(貸)/ 未收款退貨折讓(貸) |
| `1314` | 在製品 | 進貨類別「委外加工」 |
| `1315` | 原料 | 進貨類別「原料」「包材」 |
| `1315-01`~`04` | 原料 / 製成品 / 商品-各產品線 | 訂單 COGS、生產入庫,依產品線拆(`COGS_INVENTORY_ACCOUNTS`) |
| `1300` | 存貨(通用) | 沒歸屬產品線的商品 COGS |
| `1423` | 進項稅額 | 進貨 / 費用有稅額時 |
| `1611` | 房屋 | 固定資產類別「房屋建築」 |
| `1616` | 機器設備 | 固定資產類別「機器設備」「其他」(通用) |
| `1616-02` | 機器設備-運輸設備(**待確認**) | 固定資產類別「運輸設備」 |
| `1616-99` | 累計折舊(**比照正式表模式類推**) | 每月折舊分錄貸方 |
| `1691` | 辦公設備 | 固定資產類別「電腦設備」「生財器具」 |
| `2214` | 銷項稅額 | 其他收益有稅額時 |
| `3110` | 普通股股本 | 資本異動「現金增資」 |
| `3310` | 法定盈餘公積(**待確認**) | 資本異動「盈餘轉列公積」 |
| `3351` | 累積盈虧 | 資本異動「盈餘轉列公積」 |
| `4110` | 銷貨收入(通用) | 訂單,沒歸屬產品線的商品 |
| `4111-01`~`04` | 銷貨收入-各產品線 | 訂單,依商品的產品線拆(`REVENUE_ACCOUNTS`) |

## 七、已知限制

| 項目 | 說明 |
|---|---|
| 固定資產處分損益 | 處分當下沒有計算 / 記錄帳面淨值轉列處分損益的分錄 |
| 折舊回溯 | 處分日設定得比系統已經補過的折舊月份早,已經記過的未來月份不會自動回沖 |
| 部分收款退貨 | 退貨金額超過還欠的部分時,沒有自動拆成部分退現金 + 部分沖應收 |
| 付款帳戶一致性 | 「付款帳戶」是自由輸入 + 自動完成建議,不是強制下拉,同一帳戶打字不一致還是有可能發生 |
