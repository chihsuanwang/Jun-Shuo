## 一句話

**把原本一張 Excel 流水帳,變成能「開單、對帳、追物流、看毛利、抓回購」的本機管理平台 —— 資料留在自己電腦。**

---

## 現況:一張 Excel 能做什麼、不能做什麼

目前的 `2025桂圓銷售.xlsx`:

- 兩個工作表(2024 / 2025)結構相同卻分開,還有兩欄沒標題
- 「規格」一格塞了等級、重量、批號三種東西
- 「保存期限」有的填數字、有的填日期、有的填「-」
- 「交易方式」混了付款方式(現金 / 匯款)和訂單性質(公關 / 補償)
- 「備考」一格塞優惠、折讓、贈品、單據
- 同一個客戶好幾種寫法(劉麗華 / 劉麗華(基隆) / 劉麗華(宜蘭)),姓名和來源管道混在一起
- 沒有訂單編號 —— 一次出貨被拆成好幾列
- 沒有「通路」欄 —— 官網 / 市集 / 批發 / 媒體導流 全埋在文字裡
- 沒有批次、庫存、效期
- 沒有成本,所以**看不出毛利**
- 沒有收款狀態、沒有物流單號
- 夾雜空白列、項次重號、數量×單價 對不上合計的列

**結果**:查得到「誰、哪天、買了什麼」,但**算不出毛利、回購率、各通路損益、批次去化、應收帳齡**,也沒有效期預警、沒有物流異常追蹤。

## 平台把這些補起來

| 痛點 | 平台的做法 |
|---|---|
| 資料混在一格 | 拆成獨立欄位與主檔:客戶、商品(含規格 / 定價 / 單位成本)、通路各自建檔 |
| 同名 / 多寫法客戶 | 客戶資料庫 + 別名對照 + 搜尋(可搜電話)+ 重名提醒 + 合併工具 |
| 沒有訂單概念 | 一次出貨 = 一張訂單,底下掛明細;可改品項、複製、改客戶、刪除(有東西擋著會具體說明原因) |
| 看不出賺不賺 | 商品填單位成本 → 每筆算毛利;報表看依商品 / 依通路的毛利率 |
| 開單出貨不代表錢真的進來了 | 營收 / 毛利 / 成本只算「已收款 / 部分收款」訂單的實收金額,不是訂單開出來的金額 —— 標記已收款時要求實際輸入收到多少錢 |
| 毛利好看,不代表真的賺 —— 淡季照樣要付人事場租 | 稅前利潤 KPI + 損益簡表(毛利再扣運費 / 營運費用);進行中的產季只算「已經過去的月份」的營運費用,不會預先把未來的費用算進去嚇自己 |
| 前期(4–8 月開花養果)投入多少、什麼時候回本說不清楚 | 累積稅前利潤趨勢:逐月累加,線在 0 以下代表還沒回本 |
| 錢收了沒不知道 | 收款狀態 + 實收金額 + 收款日;應收帳齡分段;儀表板警示「逾期未收」 |
| 包裹出事沒紀錄 | 物流單號 + 出貨狀態;物流異常頁可一鍵開理賠重寄單 |
| 賣超過現貨不知道 | 商品品項層級的庫存(分裝入庫 → 出貨扣庫存);儀表板警示「庫存為負 / 偏低」;開單時顯示現貨 |
| 客人整單退貨麻煩 | 訂單頁一鍵「整筆退單」(全額沖銷 + 全部退回庫存);要退部分品項或折讓,進階表單也還在 |
| 送禮成本不明 | 訂單種類分「銷售 / 贈送 / 樣品」,公關成本單獨統計 |
| 一次性 vs 回頭客分不清 | 客戶分析(RFM):回購率、久未回購名單 |
| 跨年比較做不到 | 產季切換(可複選)+ 跨產季比較(疊圖) |
| 售價要怎麼訂沒有依據 | 定價試算頁:鮮果 → 龍眼乾 → 龍眼肉一路把成本串起來估算,對照售價、抓毛利空間(純估算,不寫回帳本) |

## 主檔 vs 交易(核心觀念)

系統把資料分兩種:

- **主檔**(建一次、之後一直用):銷售管道、商品目錄(含定價、單位成本)、客戶
- **交易**(每次發生記一筆):訂單 + 訂單明細

開訂單時**不是重打資料,是「挑」** —— 從既有客戶挑一位、從商品目錄挑幾樣、填數量,系統自動帶價。
好處:不用重複輸入、改一次到處對、報表才串得起來(靠同一個客戶編號 / 商品編號)。

比喻:商品目錄=菜單,客戶資料庫=常客名冊,訂單=一張出貨單。

## 系統怎麼運作(簡述)

- 一個本機小程式(Python),雙擊 `啟動.bat` 就跑起來,用瀏覽器操作。
- 資料存在一個 SQLite 檔案(`guiyuan_ledger.db`),**完全在自己電腦**,不上雲、不用登入、不連外。
- 每次啟動自動備份一份當天資料,保留最近 30 天。
- 詳細架構圖與資料關聯圖見 [系統文件.md](系統文件.md)。

## 導入流程(從現在到正式上線)

1. **導覽**:一起走一遍系統(用示範資料),理解主檔 / 交易 / 產季 / 毛利這套模型。
2. **填主檔對應表**:商品清單與定價 / 單位成本、通路清單、客戶別名合併。這步只有郡碩農創知道答案。
3. **建乾淨資料庫**:只放上一步的主檔,交易清空。
4. **腳本匯入**:把整理過的 2024 / 2025 舊資料導進來;對不上的自動進「待確認」。
5. **對帳 → 上線**:總營收、各產季筆數對得起原檔後,開始輸入新訂單。

## 目前範圍

**已完成**:主檔維護、訂單(開單 / 改單 / 複製 / 刪除)、客戶資料庫(含合併、刪除)、收款(實收金額)與出貨處理、
退貨 / 折讓(一鍵整筆退單,或進階表單登記部分退貨 / 折讓)、物流異常、待確認、
儀表板(產季複選、稅前利潤與損益簡表、產季目標 & 進度)、
三個報表分頁、CSV 匯出、自動備份、財務健康(月損益 + 累積稅前 + 毛利率趨勢)、產季目標維護、
商品品項層級的庫存(分裝入庫、盤點、報廢、超賣警示,手動登錄的可刪除)、
出貨作業(揀貨單 / 出貨標籤 / 食品標示,可列印)、進貨 / 供應商登記、固定資產卡與自動折舊、定價試算頁。

**之後可加**:歷史資料匯入(下一步)、現金水位 / 現金流 / 跑道警示、應付帳款。

**不做**:多人 / 多機、雲端、登入權限(設計為單人本機);報稅相關產出(見 [報稅參考.md](報稅參考.md))。

## 這套數字幫你做的三個決定

1. **定價與折扣要不要調** —— 從「依商品 / 依通路毛利」和「折扣佔比」看。
2. **哪個通路 / 品項要加碼或收掉** —— 從「通路營收 vs 毛利」「品項銷售結構」看。
3. **現金收得回來嗎** —— 從「應收帳齡」看,逾期太久的要積極追。
